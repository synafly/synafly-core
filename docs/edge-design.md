# Decision: a correctness-first read edge and a separate topology experiment

## Scope

The v0.2 research scope is executable read-only RPC infrastructure, not another
visualization or an unverified full-node replacement. Two experiments answer
different questions: whether ordinary caching/coalescing removes upstream work,
and whether a biological graph provides an additional routing advantage.

## Alternatives and decision

- Extending only the roadmap would not exercise blockchain RPC semantics.
- Immediately caching `latest` would require a validated canonical-chain tracking
  policy; a time-to-live alone cannot establish freshness across a reorganization.
- A full consensus light client or execution-node replacement exceeds this
  release and must not be implied by an RPC proxy.

Use a bounded, standard-library HTTP edge with a deliberately narrow policy:

1. Support `eth_getBalance`, `eth_getTransactionCount`, `eth_getCode`, and
   `eth_getStorageAt`. No signing, broadcasting, `eth_call`, tracing or admin RPC.
2. Bind the cache to an operator-pinned chain ID and genesis hash, checked against
   one configured upstream at startup. The upstream is trusted for state truth;
   this is not a consensus proof or a defense against a dishonest upstream.
3. Cache/coalesce only explicit EIP-1898 `blockHash` reads where
   `requireCanonical` is false or omitted. These requests identify a particular
   historical state, including an orphaned block if the upstream supports it.
4. Forward `latest`, `pending`, `safe`, `finalized`, block-number reads and
   `requireCanonical: true` reads without caching or coalescing. Never substitute
   a cached orphan for a canonical-state request. No freshness window is hidden.
5. Reject malformed/mismatched responses. Never cache errors. Bound request and
   response bytes, cache bytes/entries, concurrent origin work and HTTP handlers.
6. Loopback serving only, no browser CORS access, no request-address logging,
   no client-selected upstream and no redirect following.

This policy deliberately forgoes acceleration for many common wallet reads. An
origin pruned after a successful immutable read may no longer serve that state;
the cache can retain it until expiry. Error availability therefore is not promised
to mirror an origin that later prunes data. State bytes still depend on upstream
honesty. Block-hash support is a provider capability to test, not assume.

## Experiments and attribution

The HTTP experiment compares pass-through, cache-only, coalescing-only and both
using the same fixture workload. It reports actual origin request counts,
including identity checks, and encoded JSON byte counts—not a fleet cost estimate.
Concurrency is synchronized in the fixture so results do not depend on a lucky
sleep. A separate, low-volume opt-in public BSC probe checks compatibility against
a fixed block without sending transactions or using credentials.

The topology experiment uses the observed 256-node/605-edge sample, degree-matched
rewirings and a conventional equal-edge-budget overlay. Identical source/target
pairs, seeds, hop bounds and failure sets are applied to all strategies. Report
reachability and work, including unsuccessful traversals and fallback. Do not
quietly take only a well-connected component or give the biological graph extra
links. Graph routing results are controlled experiments, not WAN measurements.

The direct-socket upstream transport verifies HTTPS certificates and refuses
redirects. An after-connect shutdown timer bounds trickling responses; platform
DNS resolution remains outside that deadline guarantee. Configured remote proxy
routes are not silently bypassed: unsupported proxy configurations fail explicitly.

## Acceptance and rollback

Adversarial wire-format, state-context, error-retry, concurrency, eviction and HTTP
tests must pass. All published counts must be generated by runnable experiments.
Original continuity/registry tests remain unchanged in meaning. A negative graph
result is retained. The safe downgrade is an uncached read-only forwarder; existing
keepers and the production website are not modified or redeployed by this release.
