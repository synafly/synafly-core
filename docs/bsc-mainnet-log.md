# BSC Mainnet continuity log: operator runbook

**Contract type: INFRASTRUCTURE_CONTINUITY_LOG.** This immutable-configuration,
append-only registry is **NOT an ERC-20/BEP-20 token**, cannot be swapped/traded as
one, and contains no staking, payout, balance, supply or reward logic.
The separate ecosystem token is `0x259dd071f40d96e61f2bcc663bfac6898d957777`.
Never use that address as the registry, a witness, or a transaction destination.

## Current status and trust model

Mainnet deployment is confirmed as a **single-operator permissioned log** on BSC
(deployer: token creator wallet `0xce46009fefe328ec70b5f8cf2b02b28397f0e7ba`; registry: `0x577f89cf815d3ca533414f93b0ee94b848dfc96c`; deploy block: 122377488; genesis commit block: 122377571).
Authoritative records and receipts are in [`deployments/bsc-mainnet.json`](../deployments/bsc-mainnet.json).

The intended governance is a **single-operator permissioned log**, not independent
multi-party consensus. Three witnesses derived/managed by one operator do not add
three independent trust domains. The 2-of-3 quorum authenticates receipt sequencing
and Merkle integrity, not physical I/O savings, economic rewards or biological
correctness. Fixed genesis receipts are explicitly test content, not live BSC traffic.

The phrase “read-only state log” is avoided: `commit(...)` changes contract state.
The registry is append-only; its code/configuration is immutable and it is not a token.

## Exact unchanged contract

- Solidity `0.8.30+commit.73712a01`, optimizer enabled, 200 runs, EVM `paris`, no via-IR.
- `contracts/ContinuityRegistry.sol` and `foundry.toml` are unchanged.
- Source/config hashes, creation bytes, unpatched runtime and immutable offsets are
  pinned. The deployed threshold-2 runtime must match the computed code hash.
- Constructor is exactly `abi.encode(sorted address[3] as address[], uint256(2))`.
  The ABI encoding has array offset 64, threshold 2, length 3, then sorted addresses.
- CREATE address is computed from the actual deployer and nonce before genesis
  signing. EIP-191 binds chain ID 56 and that registry address; signatures for the
  public test fixture or a different nonce/address are not transferable.

The default requested endpoint is `https://bsc-dataseed.binance.org/`; `--rpc` may
select another bare HTTPS mainnet origin. Every broadcast checks chain ID 56 and
the known BSC genesis. Local/private-address endpoints are refused. These checks
still trust the configured RPC; they are not a consensus light-client proof.
[BNB Chain endpoint documentation](https://docs.bnbchain.org/bnb-smart-chain/developers/json_rpc/json-rpc-endpoint/).

## Install tools without exposing wallet secrets

Core tests, public plan construction, signature recovery and raw decoding use only
Python's standard library. Environment-key signing is an **optional operator-only**
path using `eth-account==0.14.0`, never a new default CI dependency.

```sh
python3.12 -m venv .local/mainnet-signing
.local/mainnet-signing/bin/python -m pip install --only-binary=:all: \
  --require-hashes -r requirements-mainnet-signing.txt
forge build --offline
```

The optional dependency lock pins 23 packages and official wheel hashes. Downloaded
wheels were checked for installation hooks (`.pth`/scripts) before isolated fixture
use. This is a scoped supply-chain check, not an audit of all dependency code.
The script never installs/upgrades packages. Funded-wallet signing requires an
operator-reviewed environment; pure-Python recovery and this harness are not an
independent security audit.

The compiler subprocess receives only basic path/locale variables, not wallet or
API key environments. Never put keys in command arguments, Git, `.env` files,
keystores generated by this repository, screenshots or issue reports.

## Offline dry-run and reproducible genesis

```sh
python3 scripts/deploy_bsc_mainnet.py dry-run --fixture \
  --artifact tests/fixtures/mainnet-build.json \
  --out .local/fixture-mainnet-plan.json
```

This needs no network, wallet, Anvil or installed signer package. The committed
`tests/fixtures/genesis_checkpoint.json` contains fixed synthetic receipts,
count-bound SHA-256 Merkle root, chain-56 EIP-191 certificate, exact constructor and
raw legacy/type-2 codec vectors. Re-running those inputs yields identical calldata.
The public test seed is reproducible and **MUST NEVER BE FUNDED**. Broadcast rejects
its deployer/witness addresses and fixture mode, even if someone relabels a plan.

Fixture regeneration is separate and optional:

```sh
.local/mainnet-signing/bin/python scripts/make_mainnet_fixture.py
```

An operator plan can be prepared without keys using explicit public addresses:

```sh
python3 scripts/deploy_bsc_mainnet.py dry-run --deployer <address> --nonce <nonce> \
  --committee <witness1> <witness2> <witness3> --out .local/mainnet-plan.json
```

Without `--artifact`, the script compiles offline using the pinned Foundry config.
Without `--online`, no RPC is contacted. Gas limits (defaults 1,200,000 deployment
and 300,000 commit) are **limits, not gas estimates**. `--online` can fetch a pending
nonce and estimate creation gas; genesis estimation requires deployed code. The
rough 840k/136k figures are not hardcoded or presented as mainnet measurements.
Gas price and exchange rates are not assumed; there is no USD-cost promise.

## Operator environment signer: derived or loaded witnesses

Provide `BSC_MAINNET_PRIVATE_KEY` privately in your **local shell**, outside chat,
logs and repository files. Do not paste a key into a command shown in this runbook.
Use a dedicated low-balance deployment account. The default total signed-fee cap is
**0.002 BNB**; a balance of 0.002 BNB does not guarantee success if fees exceed it.

```sh
.local/mainnet-signing/bin/python scripts/deploy_bsc_mainnet.py dry-run \
  --private-key-env BSC_MAINNET_PRIVATE_KEY --witness-mode derived --online \
  --max-total-fee-bnb 0.002 --out .local/mainnet-plan.json
```

Derived mode computes three dedicated keys with HMAC-SHA256, using the deployer
key as HMAC key, the fixed `SynaFly.BSC.Mainnet.ContinuityWitness.v1` domain,
chain ID 56, witness index 1–3 and a bounded rejection counter for curve scalars.
The same deployer restores the same witness accounts. The witnesses need no funds:
EIP-191 signing is local and only the deployer pays transaction fees.

`--witness-mode loaded` instead consumes all three named variables:
`BSC_WITNESS_1_PRIVATE_KEY`, `BSC_WITNESS_2_PRIVATE_KEY`,
`BSC_WITNESS_3_PRIVATE_KEY`. Missing/duplicate/invalid keys fail closed. All accounts
must be distinct from the deployer and the token address.

Values are popped from the signing process's environment and retained only in
account objects needed for signing; they are never written or printed. This does
not erase the parent shell's exports, and Python cannot guarantee memory zeroization.
Clear exports after use. Secure backup/recovery is the operator's responsibility,
outside this repository. Losing the derivation root can lose the witness committee;
compromising it compromises all derived witnesses. No committee rotation exists in
this immutable contract. This is expressly **single-operator permissioned**.

## Broadcast (operator action; not performed by this PR)

Review the dry-run's addresses, nonce, constructor, genesis scope and fee policy,
then execute locally with the same environment:

```sh
.local/mainnet-signing/bin/python scripts/deploy_bsc_mainnet.py broadcast \
  --plan .local/mainnet-plan.json --private-key-env BSC_MAINNET_PRIVATE_KEY \
  --witness-mode derived --max-total-fee-bnb 0.002 --confirm-mainnet \
  --journal .local/bsc-mainnet-journal.json
```

The signer uses `eth-account` for key operations, not the research recovery code.
Generated signatures/raw transactions are independently recovered/decoded and
checked before any send. Three constructor addresses are sorted; two valid
witness signatures are sorted and aggregated for the actual registry-bound genesis.

Alternatively, use a user-controlled external signer and pass `--certificate`,
`--raw-deploy` and `--raw-genesis` with `--plan`. The harness accepts protected
legacy EIP-155 or type-2 EIP-1559 with an empty access list. It rejects unsupported
transaction types, wrong chain/sender/nonces, nonzero native value, unexpected
initcode/calldata, token destinations and excessive fees.

Before deployment it checks the pending nonce, balance against worst-case signed
fees, and empty predicted address. It sends only the exact validated raw bytes,
waits for three confirmations, verifies constructor/runtime, rechecks committee
and empty lineage, simulates the commit, submits it, waits for three confirmations,
and verifies the exact event/transaction/head. No retry changes nonce, gas or calldata.

## Crash, RPC failure and publication status

An exclusive local journal lock prevents concurrent use of one journal. Each
computed transaction hash is durably recorded **before** sending; lost/unknown
responses stop. Re-running the same journal polls those hashes and never
re-sends them. An accepted deployment with a lost RPC response is reconciled before
continuing. Do not delete the journal or create replacement transactions blindly.
A failed transaction or reorg requires review; spent gas is not refunded by this code.

After confirmed deployment, the artifact may state `deployed_pending_genesis`.
Only confirmed, validated genesis changes it to `deployed`, includes actual hashes,
block number, committee, lineage/root, receipts and fee accounting, and updates the
claims ledger to “Deployed permissioned log, no economic claim”. It does not commit,
push or merge these resulting local file changes. Review them before publication.

Three confirmations are a policy threshold, not absolute finality. RPC/provider
honesty, DNS/TLS and chain liveness remain assumptions. The old public status is
not fabricated from a dry-run or mock test.

## BscScan source verification

The dry-run prints the exact `forge verify-contract` command with chain 56,
`--verifier etherscan`, full compiler version, optimizer 200, Paris, constructor
arguments and predicted registry address. Execute it **after** successful deployment
from this repository, using your own `ETHERSCAN_API_KEY` environment if required.
No API key is put into the printed command. The fixed compiler/bytecode must match;
do not flatten, change settings or use `--force` to conceal a mismatch.

A link to `https://bscscan.com/address/<registry>#code` is not proof of verification.
The artifact retains `bscscan_verification_status: not_requested` until the operator
actually verifies it and reviews the explorer result.
[Official Foundry verification instructions](https://docs.etherscan.io/contract-verification/verify-with-foundry).
